## Usage

```tsx
import { SingleSelectV2 } from '@juspay/blend-design-system'

function MyComponent() {
    const [selected, setSelected] = useState('')
    const items = [
        {
            groupLabel: 'Countries',
            items: [
                { label: 'United States', value: 'us' },
                { label: 'United Kingdom', value: 'uk' },
                { label: 'Canada', value: 'ca' },
            ],
        },
        {
            groupLabel: 'Asia',
            items: [
                { label: 'Japan', value: 'jp' },
                { label: 'Singapore', value: 'sg' },
            ],
        },
    ]

    return (
        <SingleSelectV2
            label="Select Country"
            placeholder="Choose a country..."
            selected={selected}
            onSelect={setSelected}
            items={items}
            search={{ show: true, placeholder: 'Search countries...' }}
        />
    )
}
```

## Server-side search

Put `searchText` in the `search` config to make search controlled. The component
renders that value, calls `onSearchChange` for every input change, and does not
filter `items`; the consumer supplies already-filtered API results.

```tsx
<SingleSelectV2
    label="Find a person"
    placeholder="Select a person"
    items={apiResults}
    selected={selected}
    onSelect={setSelected}
    search={{
        searchText: query,
        onSearchChange: setQuery,
        isSearchLoading: isSearching,
        emptyStateText: query ? 'No people found' : 'Start typing to search',
    }}
/>
```

Controlled mode is selected by the presence of `search.searchText`, including an
empty string. Omitting `onSearchChange` creates a read-only search input.
`show: false` hides the input but still disables internal filtering. Debouncing,
request cancellation, caching, and errors remain consumer responsibilities;
search loading is independent from pagination via `hasMore`/`loadingComponent`.

The controlled query persists when the menu closes and reopens. Clear it in
your own lifecycle handler only when that is the experience you want, for
example with `onOpenChange={(open) => !open && setQuery('')}`.

| `SingleSelectV2` search field | Legacy `SingleSelect` equivalent |
| ----------------------------- | -------------------------------- |
| `search.searchText`           | `searchText`                     |
| `search.onSearchChange`       | `onSearchChange`                 |
| `search.isSearchLoading`      | `isSearchLoading`                |
| `search.emptyStateText`       | `emptyStateText`                 |

## Localization

SingleSelectV2 has 6 built-in strings: 4 shown on screen, 1 placeholder and 1 read only by screen readers. Everything else it renders comes from your props and data.

| Key                                | English default      | Where it appears |
| ---------------------------------- | -------------------- | ---------------- |
| `common.empty.no-items`            | `No items available` | On screen        |
| `common.empty.no-results`          | `No results found`   | On screen        |
| `select.a11y.search`               | `Search options`     | Screen reader    |
| `select.label.custom-value`        | `Specify`            | On screen        |
| `select.label.custom-value-option` | `{label}: "{value}"` | On screen        |
| `select.placeholder.search`        | `Search options...`  | Placeholder      |

All keys are also listed in the [message catalog](/docs/internationalization/message-catalog#select), under [`common.*`](/docs/internationalization/message-catalog#common) and [`select.*`](/docs/internationalization/message-catalog#select).

`common.*` is shared with 7 other components, so translating it once covers all of them.

`select.*` is shared with MultiSelect, MultiSelectV2, SelectListV2 and SingleSelect, so translating it once covers all of them.

### Translating

Pass a `locale` and a `t` function to `ThemeProvider`. Any key you don't translate falls back to its English default.

```tsx
import { ThemeProvider, createTranslator } from '@juspay/blend-design-system'

const t = createTranslator({
    'select.label.custom-value': 'Préciser',
    'select.a11y.search': 'Rechercher des options',
})

export function Root() {
    return (
        <ThemeProvider locale="fr-FR" t={t}>
            <App />
        </ThemeProvider>
    )
}
```

Using i18next, FormatJS or another library? Pass its translate function as `t` instead; see [Internationalization](/docs/internationalization/overview).

### Changing one string

A prop replaces one string for that instance and always wins over `t`:

| Prop                 | Replaces key                | English default     |
| -------------------- | --------------------------- | ------------------- |
| `customValueLabel`   | `select.label.custom-value` | `Specify`           |
| `search.placeholder` | `select.placeholder.search` | `Search options...` |

Don't pass a prop just to restate the English default: it wins over `t`, so that string would stay English in every locale.

### Notes

- Option labels are your data.
